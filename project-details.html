Project 01 · AI + Web Platform · In Progress

Code Guard AI

An Agentic AI-powered website development and deployment concept designed to help users move from an idea to a deployed website. The platform aims to generate a website from a user's prompt, review the code, identify common errors, check dependencies, examine security risks, and guide the deployment process before sharing a live website link.

ReactNode.jsAgentic AI ConceptsCode AnalysisSecurity ValidationDeployment Automation

01 / Project overview

Building and deploying a website can involve several separate tasks: creating the code, finding errors, installing dependencies, reviewing security, and configuring deployment. These steps can be difficult for beginners and may require switching between multiple tools.

Code Guard AI brings these tasks into one planned workflow. A user starts by describing the website they want. The platform is intended to help create the initial website, then review and prepare the project for deployment. Users can also provide a GitHub repository link after creating their website so the platform can analyse the source project.

02 / Problem statement

Website development and deployment often require manual debugging, dependency management, security checks, and deployment configuration. Missing a step can cause build failures, broken pages, or security concerns. Beginners may find it difficult to identify what needs to be fixed before publishing a website.

Proposed solution: provide a guided, AI-assisted workflow that reviews the project, highlights issues, supports fixes, validates important security concerns, and helps prepare the website for deployment.

03 / Key features

FEATURE 01

Prompt-based website creation

The user describes the website they want, and the platform is designed to use AI assistance to generate an initial website project.

FEATURE 02

GitHub project import

After creating a website, the user can provide a GitHub repository link for source-code review and deployment preparation.

FEATURE 03

Code review and error detection

Analyse project files to identify likely code errors and build issues, then suggest or support appropriate corrections.

FEATURE 04

Dependency checks

Check required packages and dependencies so missing or inconsistent requirements can be identified before deployment.

FEATURE 05

Security validation

Review for common security concerns, exposed secrets, and risky configuration. External API usage should be identified and flagged for review rather than treated as automatically safe.

FEATURE 06

Deployment and report

Guide the deployment workflow and aim to provide the resulting live website link along with a summary of checks and deployment status.

04 / How it is intended to work

01

Login and open the dashboard

The user enters the platform and starts a new website project from the dashboard.

02

Describe the website

The user enters a prompt describing the purpose, pages, and expected features of the website.

03

Generate or import the project

AI assistance helps create the initial website. Alternatively, the user can provide a GitHub repository link for an existing project.

04

Review code and dependencies

The platform checks project files for possible errors, build issues, and missing dependencies, then presents findings and possible fixes.

05

Run security checks

Review configuration, exposed credentials, and external API usage. Flag items that need user approval or manual review before deployment.

06

Prepare deployment and show results

After the required checks, continue with deployment and show the live link and a report of the checks performed and any remaining warnings.

Security note: automated checks can reduce risk, but they cannot guarantee that a project is completely secure. Secrets should not be exposed in source code, and external API connections should be reviewed before use.

05 / Technologies and tools

React.jsFrontend user interface
Node.jsBackend and project workflow
Agentic AI conceptsTask-oriented assistance
GitHubRepository source and version control
Security checksReview and validation stage
Cloud deploymentTarget publishing workflow

The project is being developed as a learning and implementation project. The listed technologies describe the planned/current project direction; individual automated checks and deployment integrations depend on the implementation completed.

06 / Expected outcome

Code Guard AI aims to make the website preparation process more organised and beginner-friendly by bringing code review, dependency checks, security review, and deployment guidance into one place. The expected result is a clearer development workflow, earlier visibility of common problems, and a deployment summary that helps the user understand what was checked.

Project 02 · IoT + Hardware · Team Project

Equal Distribution
of Water

An IoT-based hardware project focused on a common real-world problem: water may not reach every connected area or user in a balanced way. The project explores how monitoring and controlling water flow can help distribute available water more evenly and reduce avoidable wastage.

Internet of ThingsWater ManagementHardware PrototypeTeam ProjectResource Efficiency

01 / Project overview

The aim of Equal Distribution of Water using IoT is to explore a smarter way to manage water distribution. In a basic manual arrangement, water flow can vary because of pressure differences, uneven demand, or the way outlets are opened and closed. This can cause some outlets to receive more water while others receive less.

An IoT approach can combine sensing, a controller, and water-flow control components so the system can observe conditions and respond according to its design. The overall goal is fairer distribution, better visibility of the system, and more responsible use of water. This was a team hardware project and was recognised in a project competition.

02 / Problem statement and objective

Problem: uneven water distribution can lead to shortages at some outlets, excess flow at others, and inefficient use of a limited resource. Manual monitoring may also make it difficult to notice imbalances quickly.

Objective: develop an IoT-oriented solution concept that can monitor relevant water-distribution conditions and help manage flow so that connected destinations receive a more balanced share according to the system's rules.

OBJECTIVE 01

Fairer distribution

Work toward reducing differences in water availability between connected outlets or sections.

OBJECTIVE 02

Monitoring

Make the condition of the water system easier to observe than relying only on manual checks.

OBJECTIVE 03

Reduce wastage

Support more careful use of water by identifying imbalances or unnecessary flow where the design allows.

OBJECTIVE 04

Automation potential

Use sensor information and controller logic to support timely responses instead of depending entirely on manual operation.

03 / How the system works — concept

01

Water enters the distribution setup

A source supplies water to a pipe or distribution network connected to the required outlets or sections.

02

Conditions are monitored

In an IoT implementation, suitable sensors may measure flow, level, or another parameter relevant to the prototype's design.

03

The controller evaluates readings

A microcontroller can compare the sensor readings with the distribution rules and determine whether an outlet needs more or less flow.

04

Flow is adjusted when supported

Depending on the actual hardware, a control mechanism such as a valve or pump can be used to change flow and improve balance.

05

Status can be shared

With suitable connectivity and software, system readings or status can be made available for remote monitoring. This depends on the features implemented in the prototype.

The exact sensors, controller board, valve/pump arrangement, and communication method were not specified in the portfolio information available. The steps above describe a typical IoT system concept; they should be edited to match the components actually used in your project.

04 / Main modules

MODULE 01

Sensing layer

Collects water-related readings, such as flow or level, if those sensors are part of the design.

MODULE 02

Controller and logic

Processes readings and applies the project's distribution rules.

MODULE 03

Water-flow mechanism

Routes or regulates water through the physical setup, depending on the hardware chosen.

MODULE 04

IoT monitoring

Provides connectivity or status display if the prototype includes a communication and monitoring interface.

05 / Applications, benefits and challenges

Potential applications: small-scale water distribution demonstrations, educational IoT prototypes, irrigation experiments, storage-tank management, or other settings where water flow needs to be monitored. Suitability for a real installation depends on testing and system design.

Expected benefits: better visibility of water flow, a more systematic approach to balancing distribution, reduced need for constant manual observation, and awareness of water conservation.

Engineering challenges: sensor accuracy, varying inlet pressure, blockages or leaks, reliable connectivity, safe operation around water and electronics, and choosing a fair distribution rule for different demand levels.

My learning: this project provided experience in approaching a practical resource-management problem through a hardware and IoT perspective, collaborating as a team, and considering how monitoring and control can improve a physical system.

Project 03 · Renewable Energy + Hardware

360° Solar Tracker

A hardware project designed to adjust a solar panel's direction as the apparent position of the Sun changes. The central idea is to let the panel face the sunlight more directly over a wider range of angles, helping it capture available sunlight more effectively than a fixed panel under suitable conditions.

Solar EnergySunlight TrackingHardwarePanel OrientationEnergy Optimisation

01 / Project overview

A fixed solar panel stays in one direction even though the Sun's apparent position changes throughout the day. Because the angle of incoming sunlight changes, the panel may not always receive light at the most favourable angle.

The 360° Solar Tracker project explores moving or orienting the panel so it can follow sunlight across a wide range of directions. The goal is to make better use of the available sunlight and improve the panel's exposure as conditions change. The term “360°” describes the intended broad rotational tracking range; the actual movement depends on the mechanical design and its limits.

02 / Problem statement and objective

Problem: a fixed panel cannot continually change its orientation to follow the Sun. At some times, sunlight arrives at an angle that is less favourable for the panel.

Objective: design a tracking mechanism that changes the panel's orientation toward the brighter direction, with the intention of improving sunlight capture during the day.

GOAL 01

Follow sunlight

Detect or determine the direction with stronger sunlight and orient the panel toward it.

GOAL 02

Wide-angle movement

Provide broad rotational coverage within the limits of the mount, motors, wiring, and control system.

GOAL 03

Use sunlight effectively

Reduce avoidable misalignment between the panel and incoming sunlight during tracking periods.

GOAL 04

Explore automation

Use a control process to adjust orientation instead of relying only on manual repositioning.

03 / How it works — concept

01

Sunlight reaches the sensing arrangement

A tracking design may use light sensors arranged to compare brightness from different directions, or it may calculate the Sun's position using time and location.

02

The controller compares the direction

A controller interprets the sensor readings or position calculation and determines whether the panel should move.

03

The drive mechanism rotates the panel

A suitable motor and mechanical mount adjust the panel's direction. A true full-range 360° design needs to account for mechanical stops, cable twisting, stability, and safe movement.

04

Tracking repeats as sunlight changes

The system periodically checks the direction and makes small adjustments so the panel can continue to face a favourable direction.

05

Solar output can be compared

To evaluate the project, output from the tracking panel can be compared with a fixed panel under similar sunlight and time conditions, if measurement equipment is available.

A 360° tracker can mean full azimuth rotation, while some solar trackers use two axes to change both horizontal direction and tilt. The exact movement, sensor type, controller, and motor depend on the hardware actually built. This description explains the general concept and does not assume a specific component list.

04 / Main modules and components

MODULE 01

Solar panel

Converts incident sunlight into electrical energy.

MODULE 02

Sun-position sensing

May use light sensors or a calculated Sun position to guide panel movement.

MODULE 03

Controller

Processes readings and decides when and in which direction the panel should move.

MODULE 04

Motor and mount

Provides controlled physical movement while supporting the panel securely.

MODULE 05

Power and wiring

Supplies the control system and safely connects sensors, drive components, and panel measurement points.

MODULE 06

Output measurement

Voltage, current, or power readings can help evaluate whether tracking improves performance.

05 / Benefits, challenges and applications

Potential benefits: improved alignment with sunlight during suitable conditions, automated panel positioning, a practical demonstration of renewable-energy technology, and a way to study how panel orientation affects output.

Potential applications: educational solar-energy prototypes, demonstrations of tracking control, and small-scale experiments comparing fixed and tracking panel orientations. Actual energy gains depend on location, weather, tracking accuracy, panel geometry, motor energy consumption, and maintenance.

Engineering challenges: sensor readings can be affected by clouds or shadows; motors consume energy; the mount must withstand wind and panel weight; and wiring, movement limits, calibration, and outdoor protection need careful consideration.

How to evaluate it: record voltage and current from the panel over the same period for fixed and tracking positions, under comparable conditions. Comparing power (voltage × current) and energy over time provides a stronger evaluation than observing movement alone.

My learning: this project connects hardware design with renewable energy and automation. It highlights how sensing, control logic, and mechanical movement can work together to solve a real-world energy-use problem.

Project 04 · UPI Security + Fraud Prevention · Concept

Secure UPI

Secure UPI is a payment-safety project concept intended to help users check a QR code before making a UPI payment. It scans the QR data, examines the payment address and displayed payee details for warning signs, and gives the user a chance to review the information before continuing to a trusted UPI app to authorise the payment.

QR Code ScanningUPI ID ValidationFraud AwarenessPayment ConfirmationSecurity-first UX

01 / Project overview

QR codes make digital payments quick, but a user can be tricked into scanning a code that sends money to an unintended recipient. Secure UPI is designed as an extra review step before payment. Instead of asking users to trust a QR code blindly, the system aims to read the QR contents, show the destination UPI ID and payee information when available, and flag details that appear invalid or suspicious.

The intended outcome is to help users make a more informed decision before they approve a transaction. The app should not collect or store a UPI PIN, OTP, or banking password. Actual payment authorisation should happen inside a trusted UPI app or payment provider.

02 / Problem statement and objectives

Problem: people may scan a substituted or misleading QR code without noticing that the payment recipient is different from the person or business they intended to pay. A QR code can contain syntactically valid data and still be used fraudulently.

Objective: create a clear verification flow that checks the QR data, displays recipient information, warns about detectable issues, and lets the user decide whether to proceed.

OBJECTIVE 01

Scan the QR code

Read the QR payload using the device camera or an uploaded QR image, with the required camera permission.

OBJECTIVE 02

Inspect payment details

Parse the UPI payment address and other supported fields, then check that the data follows the expected format.

OBJECTIVE 03

Make recipient clear

Show the UPI ID and available recipient or merchant information so the user can compare it with the intended payee.

OBJECTIVE 04

Warn before payment

Flag invalid or unexpected details and ask the user to stop and verify them when anything looks suspicious.

03 / How the project works

01

Open Secure UPI

The user opens the scanner and grants camera access if they choose to scan a live QR code.

02

Scan and decode

The scanner reads the QR content and checks whether it appears to be a supported UPI payment payload. If it cannot be decoded or parsed, it should not continue automatically.

03

Validate the details

The app checks the structure of the UPI address and relevant fields, and identifies missing, malformed, or unexpected values that it knows how to detect.

04

Review recipient information

The screen shows the available payee name, UPI ID, and amount if the QR includes one. The user should compare these details with the intended recipient.

05

Warn or continue

If the QR data is invalid or a check raises a warning, the app asks the user to stop and verify. If the details look acceptable, the user may choose to open a trusted UPI app to continue.

06

Authorise payment securely

The user confirms the recipient and amount and completes authorisation in the UPI app. Secure UPI should never request or store the user's UPI PIN or OTP.

Important security limitation: QR format checks can identify some invalid or suspicious data, but they cannot prove that a QR code is genuine or guarantee that a payment is safe. A valid QR may still point to a fraudster. Users must verify the payee and amount in the trusted payment app before entering their UPI PIN.

04 / Main modules

MODULE 01

QR Scanner

Captures QR information through the camera or an image selection feature.

MODULE 02

QR Parser

Decodes the payload and extracts supported UPI payment fields.

MODULE 03

Validation Engine

Checks required fields, UPI address format, and known invalid or unexpected patterns.

MODULE 04

Recipient Review Screen

Presents the available recipient and amount details in a readable confirmation screen.

MODULE 05

Risk Warning

Displays clear warnings when checks fail and avoids silently opening a payment flow after an invalid scan.

MODULE 06

Trusted Payment Handoff

Offers a user-controlled handoff to a supported UPI app; final authorisation remains with the payment provider and user.

05 / Benefits, applications and challenges

Potential benefits: an extra review step before paying, better visibility of the destination UPI ID, clearer warnings, and greater awareness of QR-payment risks.

Potential applications: shop QR payments, merchant-payment demonstrations, student security projects, and user education about checking payment details before authorisation.

Engineering challenges: different QR formats, incomplete recipient information, camera and lighting quality, false alarms, privacy, safe payment-app integration, and keeping validation rules up to date.

How to evaluate it: test with known-good sample UPI QR codes, malformed QR data, unsupported payloads, and test cases with altered recipient details. Measure successful scans, correct parsing, warning accuracy, and whether the user clearly sees the payee details before the payment handoff. Use test data only; do not test by sending money to unknown recipients.

My learning: this project explores how QR scanning, data validation, user confirmation, and secure payment handoff can be combined to make digital payment flows more safety-conscious.
